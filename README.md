# 🌏 URTH : Culture Guardian

> A chatbot that helps users talk with friends from other cultures by filtering biased questions and answering with culture-specific RAG context.

<br>

## Overview

Questions about other cultures can unintentionally carry stereotypes or offensive framing. Culture Guardian classifies the intent of each question with a fine-tuned Korean RoBERTa model, double-checks suspicious ones with GPT, and answers the rest using etiquette knowledge retrieved per country. The project was built as a Data Science capstone design project (Fall 2025).

<br>

## Approach

- **Data**
  - Intent dataset: 3,858 Korean questions labeled 호기심/정보요청 (0), 비하/도발 (1), 편견 (2), split 80/10/10 with stratification
  - RAG corpus: 28,195 etiquette passages for 277 countries/regions (CultureBank, CultureCrossing, MOFA PDF), 659 group-relation notes, multilingual country aliases
  - Evaluation set: 200 yes/no etiquette questions across 20 countries
- **Preprocessing**
  - Removes samples that the model confuses between 편견 and 비하/도발 (`*_clean.csv` splits)
  - Splits RAG passages into 512-character chunks and embeds them into a Chroma vector DB, excluding the evaluation questions
- **Model**
  - Intent classifier: `klue/roberta-large` fine-tuned with label smoothing, R-Drop and EMA
  - Chatbot pipeline: intent filter → GPT secondary check for 비하/도발 → per-user memory slots → country-prioritized RAG search → persona prompt → `gpt-4o-mini` answer
- **Evaluation**
  - Intent classifier: accuracy, macro F1/precision/recall, MCC and purity on the validation and test splits
  - RAG: Hybrid RAG vs Non-RAG yes/no accuracy, F1, MCC, BLEU and BERTScore for OpenAI, Claude, Gemini and Clova

<br>

## Results

| Model | Metric | Score |
|---|---|---|
| Intent classifier (`klue/roberta-large`) | Test macro F1 | Run `python test.py` |
| Hybrid RAG vs Non-RAG (per LLM) | Accuracy / F1 | Run `python rag_eval.py --model all` |

- `test.py` writes metrics, a confusion matrix, a classification report and misclassified samples to `models/intent_classifier/klue_roberta_experiment/`
- `rag_eval.py` writes per-model metrics and per-question answers to `data/eval/results/`

## Getting Started

### Setup

```bash
pip install -r requirements.txt
cp .env.example .env           # Fill in OPENAI_API_KEY (and other keys for rag_eval.py)
```

A GPU is recommended for training: `klue/roberta-large` does not fit comfortably in CPU memory.

### Intent Classifier

The splits in `data/intent/splits/` are already prepared. To regenerate them:

```bash
python prepare_data.py split   # intent_dataset_final.csv → train/valid/test.csv
python prepare_data.py clean   # Uses misclassified_samples.csv from test.py → *_clean.csv
```

Train, validate and test (all default to `configs/klue_roberta.yaml`):

```bash
python train.py
python valid.py
python test.py
```

The best checkpoint is saved to `models/intent_classifier/klue_roberta_experiment/best_model.pt`.

### Chatbot

```bash
python build_vectordb.py       # Embeds data/rag/raw_json/ into data/rag_repository/
python app.py                  # Add --no-share to skip the public gradio.live link
```

`app.py` needs the trained checkpoint and the vector DB. User accounts and memory are stored in `data/users/`.

### RAG Evaluation

```bash
python rag_eval.py --model openai   # openai | claude | gemini | clova | all
```

<br>

## Notes

- `data/rag/raw_json/` also holds the 200 evaluation questions with answers (`source: "eval_dataset"`); `build_vectordb.py` skips them so the RAG evaluation does not see its own answers
- The best checkpoint stores the EMA weights that produced the best validation F1
- Claude evaluation now uses current models (`claude-sonnet-5-5`, then `claude-opus-5-5`, then `claude-haiku-4-5`) because the original Claude 3 models are retired
- User passwords are stored as salted PBKDF2 hashes in `data/users/`; the app is still a demo, not a production service
